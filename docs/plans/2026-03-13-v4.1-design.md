# A11y Crawler v4.1 — Post-Pipeline: New Tests + Regression Diff

> Builds on the v4.0 three-phase pipeline (SCAN→CLASSIFY→PROBE).
> Scope defined in the v4.0 design doc's phased delivery table and regression section.

## Scope

Three axes plus coherence fixes identified during design review.

### Axis 1: Target Size (WCAG 2.5.8)

Custom `page.evaluate()` test (~15-25ms). Detects interactive elements with bounding box < 24×24px.

**Elements checked**: `a`, `button`, `input`, `select`, `textarea`, `[role="button"]`, `[role="link"]`, `[role="checkbox"]`, `[role="radio"]`, `[role="tab"]`, `[role="menuitem"]`, `[tabindex]`.

**Algorithm**:
```typescript
async function testTargetSize(page: Page, url: string): Promise<Issue[]> {
  return page.evaluate(() => {
    const INTERACTIVE = 'a, button, input, select, textarea, [role="button"], [role="link"], [role="checkbox"], [role="radio"], [role="tab"], [role="menuitem"], [tabindex]:not([tabindex="-1"])';
    const MIN_SIZE = 24;
    const issues: Array<{ selector: string; html: string; width: number; height: number }> = [];
    for (const el of document.querySelectorAll(INTERACTIVE)) {
      const rect = el.getBoundingClientRect();
      if (rect.width === 0 && rect.height === 0) continue; // hidden
      if (rect.width < MIN_SIZE || rect.height < MIN_SIZE) {
        issues.push({
          selector: /* CSS path */,
          html: el.outerHTML.slice(0, 200),
          width: Math.round(rect.width),
          height: Math.round(rect.height),
        });
      }
    }
    return issues;
  });
}
```

**Supplements** axe-core's `target-size` rule (already runs via `wcag22aa` tags in PROBE). Our custom check catches elements axe misses (inline links, custom role elements).

**Execution slot**: Tier A — evaluate-only parallel group in `probe.ts` (alongside multimedia, timed-events). No DOM mutation, no viewport change.

**Test plan**: Unconditional — added to every template's `buildTestPlan()`.

**Template amplification**: Yes — `TEMPLATE_LEVEL_RULES` in `probe.ts:13` already includes `"target-size"`.

**checkSource**: `"wcag-custom"` (same as reflow, text-spacing, etc.)

### Axis 2: Error Identification (WCAG 3.3.1-3.3.3)

Form interaction test (~1-2s per form). Submit empty forms and verify accessible error handling.

**Algorithm**:
```typescript
async function testErrorIdentification(page: Page, url: string): Promise<Issue[]> {
  const SKIP_ACTIONS = /payment|checkout|stripe|paypal|oauth|login|signin|signup|register/i;

  const forms = await page.$$('form');
  const issues: Issue[] = [];

  for (const form of forms) {
    // Safety: skip payment/auth forms
    const action = await form.getAttribute('action') ?? '';
    if (SKIP_ACTIONS.test(action)) continue;

    // Check if form has required fields (skip forms without validation expectations)
    const requiredFields = await form.$$('[required], [aria-required="true"]');
    if (requiredFields.length === 0) continue;

    // Snapshot current URL to detect navigation
    const urlBefore = page.url();

    // Submit without filling fields
    const submitBtn = await form.$('button[type="submit"], input[type="submit"], button:not([type])');
    if (!submitBtn) continue;
    await submitBtn.click();
    await page.waitForTimeout(500); // Allow DOM updates

    // Detect navigation — go back immediately
    if (page.url() !== urlBefore) {
      await page.goBack({ waitUntil: 'domcontentloaded' });
      issues.push(/* 3.3.1: form navigates without client-side validation */);
      continue;
    }

    // Check for accessible error indicators
    const hasAriaInvalid = await form.$$('[aria-invalid="true"]');
    const hasRoleAlert = await page.$$('[role="alert"]');
    const hasAriaDescribedby = await form.$$('[aria-invalid="true"][aria-describedby]');

    if (hasAriaInvalid.length === 0) {
      issues.push(/* 3.3.1: no aria-invalid after empty submission */);
    }
    if (hasRoleAlert.length === 0) {
      issues.push(/* 3.3.1: no role="alert" for error announcement */);
    }
    if (hasAriaInvalid.length > 0 && hasAriaDescribedby.length === 0) {
      issues.push(/* 3.3.3: aria-invalid present but no aria-describedby for error description */);
    }
  }

  return issues;
}
```

**Safety filters**:
- Skip forms with `action` matching `payment|checkout|stripe|paypal|oauth|login|signin|signup|register`
- Skip forms without `[required]` or `[aria-required="true"]` fields
- Detect post-submit navigation → `page.goBack()` immediately
- Never fill fields — only test empty submission error handling

**Execution slot**: New sequential slot in `probe.ts` after axe-full and before interactive tests. Submitting forms mutates DOM state, so it must run before interactive tests check tab order. Must NOT run in the evaluate-only parallel group because it performs click actions.

**Test plan**: Conditional — only when `cluster.capabilities.hasForms === true`.

**Template amplification**: No — error identification is content/form-specific, not structural. Issues only reported for the representative page.

**checkSource**: `"wcag-custom"`

### Axis 3: Regression Diff

Automatic comparison between current audit and the most recent completed audit for the same domain.

**Trigger**: Post-completion step in the pipeline. After `markAuditCompleted()`, a separate `computeAndPersistRegression()` function queries the previous audit, computes the diff, and writes to `audits.regression`.

**Why post-step (not inline)**:
- Pipeline stays fast — regression can fail independently without affecting audit completion
- Decoupled — can retry or recompute without re-running the entire pipeline
- Previous audit query is a separate DB concern from the audit write

**Template matching algorithm** (from v4.0 design doc):

```typescript

  current: TemplateCluster[],
  previous: TemplateCluster[],
): Map<string, string> {
  const matches = new Map<string, string>(); // current.id → previous.id

  // Pass 1: URL pattern (most stable — site structure rarely changes)
  // Pass 2: Near-fingerprint (Hamming ≤ 12, wider than clustering ≤ 8)
  // Pass 3: Representative URL overlap
  return matches;
}
```

**Regression diff structure**:
```typescript
interface RegressionDiff {
  previousAuditId: string;
  previousAuditDate: string;
  matched: Array<{
    currentTemplateId: string;
    previousTemplateId: string;
    matchMethod: "url-pattern" | "fingerprint-near" | "representative-url";
    newIssues: Array<{ rule: string; impact: string; count: number }>;
    resolvedIssues: Array<{ rule: string; impact: string; count: number }>;
  }>;
  unmatchedNew: string[];      // templates only in current audit
  unmatchedRemoved: string[];  // templates only in previous audit
  scoreChange: number | null;  // current wcag_score - previous wcag_score
  summary: {
    totalNewIssues: number;
    totalResolvedIssues: number;
    newTemplates: number;
    removedTemplates: number;
  };
}
```

**Data flow**:
1. Pipeline completes PROBE → `markAuditCompleted()` (now includes `template_clusters`)
2. `computeAndPersistRegression(auditId, domain)`:
   - Query: `SELECT id, template_clusters, wcag_score FROM audits WHERE url LIKE $domain AND status = 'completed' AND id != $auditId ORDER BY finished_at DESC LIMIT 1`
   - If no previous audit → write `regression = null`, done
   - Deserialize both `template_clusters` → run `matchTemplatesAcrossAudits()`
   - For each matched pair, query issues by template_id from both audits → compute newIssues/resolvedIssues
   - Compute scoreChange from wcag_score values
   - `UPDATE audits SET regression = $diff WHERE id = $auditId`

**Frontend**: New "Regresión" tab in audit-detail (5th tab alongside Issues, Pages, Shared, Summary). Shows:
- Score change badge (↑ green / ↓ red / = neutral)
- Summary cards: new issues, resolved issues, new templates, removed templates
- Matched templates table: template name, match method, new/resolved issue counts
- Expandable rows: list of specific new/resolved rules per template

## Coherence Fixes (from design review)

These gaps exist in the v4.0 codebase and must be fixed for v4.1 to work.

### Fix 1: Persist `template_clusters` in `markAuditCompleted()`

**Files**: `src/worker/db.ts`, `src/worker/pipeline.ts`

Currently `audits.template_clusters` is always NULL. The pipeline must serialize clusters (slim format: `id`, `fingerprint`, `urlPattern`, `urls`, `representative` — strip `lightIssues` to keep payload small) and pass them to `markAuditCompleted()`.

### Fix 2: Compute and persist `wcag_score` in the pipeline

**Files**: `src/worker/pipeline.ts`, `src/worker/db.ts`

Currently hardcoded to `null` at `pipeline.ts:167`. After PROBE completes, query issue counts by impact from the DB (or aggregate in-memory) and call `computeWcagScore()` from `src/reporter/wcag-score.ts`.

### Fix 3: Add `regression` write path (full stack)

**Files**: `src/worker/db.ts`, `src/server/routes/audits.ts`, `src/server/types.ts`, `frontend/src/lib/api.ts`

New function `updateAuditRegression(auditId, diff)` in `worker/db.ts`. Add `regression` to `mapAuditRow()`, `AuditResponse` type (server), and frontend `AuditResponse` type.

### Fix 4: Add `TestType` values

Add `"target-size"` and `"error-identification"` to the `TestType` union.

### Fix 5: Update `buildTestPlan()`
